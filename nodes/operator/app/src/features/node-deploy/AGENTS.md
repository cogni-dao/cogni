## Where a node deploys from (story.5127)

`POST /deploy/workloads` deploys a node from ITS OWN repo, not the operator's.

1. **Repo.** The route calls `NodeSourceResolverPort.resolveNodeSource({nodeId, parentOwner, parentRepo})` (`createNodeSourceResolver`, story.5137). It reads the node's row from the catalog baked into the operator image (`ImageCatalogNodes`, `/app/infra/catalog`; the same catalog the sequencer uses) and checks it with `parseRemoteSourceCatalogRow`. It makes NO GitHub read of a parent repo, so flight (candidate-a) and production are the same call and differ only in env. A remote-source node (has `source_repo`) returns its own `{owner, repo}` plus `image_repository` (`ghcr.io/<owner>/<repo>`). An in-repo node (the operator) returns the env's parent repo with `imageRepository: null`. A node the image does not know is 404 `catalog_missing`.
2. **Declarations.** `.cogni/repo-spec.yaml` and `.cogni/workloads/*.yaml` are read from that repo at `sourceSha` (DECLARED_AT_THE_SHA). The read (`createDeclarationReader`) tries the operator App first. Only when the App is NOT installed on that repo (error code `github_app_not_installed`) does it read anonymously (`raw.githubusercontent.com` for files, the unauthenticated REST contents API for the one directory listing). That path needs no secret, never writes, and works only for a PUBLIC repo; any other App failure is thrown, never masked by the public read. The repo-spec `node_id` must equal the requested node (`node_mismatch`).
3. **Built image (ALWAYS_DEFER).** A manifest image of `.` means "the image node CI built at this sha". The route NEVER waits on node CI and never reads the registry, in any env, for any caller: it lowers `.` to `<image_repository>:sha-<sha>` with `imagePending: true` (`pendingImage`). The sequencer's `pinImage` resolves the digest through `BuiltImageResolverPort` (anonymous ghcr.io OCI API: pull token, `HEAD /v2/<path>/manifests/sha-<sha>`, `Docker-Content-Digest`) BEFORE any attempt row exists. While the image is absent it is `DependencyNotReady` (step `dependency/waiting`, nothing paid, retried every tick); a registry failure waits too; past `imageAlertMs` (30 min) it raises `alert/image_not_published`. The digest is pinned WRITE-ONCE on the release (`StorePort.pinResolvedImage`, column `node_workload_releases.resolved_image`, `UPDATE ... WHERE resolved_image IS NULL`) and the store returns the spec with that digest and no `imagePending`, so every attempt of a release deploys one image and a mutable tag never reaches a create. An in-repo node has no image repository, so `.` stays `built_image_unresolved` (422) and its manifest pins images by digest.
4. **Latest release wins.** A new release for the same `(node, env, workload)` moves the desired row to itself in the same transaction. An older release that never started (for example its image never appeared) is superseded: it gets no attempt and no registry read, and an in-flight attempt of an older release that has not been proven is failed `superseded`.

## One front door, every env (story.5137)

The production operator serves `candidate-a`, `preview` and `production` for canonical Akash nodes (the fleet control env reconciles every Akash lane). The route refuses (`app/api/v1/deploy/workloads/_lib/lane.ts`):

- **(a)** an env outside `NODE_DEPLOY_ENVS` (default: only `DEPLOY_ENVIRONMENT`) with 409 `env_not_served`;
- **(b)** a node this fleet does not own with 409 `node_not_in_fleet` (catalog `source_repo` org != `NODE_SUBMODULE_PARENT_OWNER`, case-insensitive; `isFleetOwnedRow`), or a lane whose `controlEnvFor(env, provider, FLEET_CONTROL_ENV)` is not the fleet control env (`env_not_served`). The test operator therefore refuses canonical toks5;
- **(c)** a record for a lane whose catalog `compute_api[env]` is not `node-deploy` with 409 `node_not_on_deploy_verb`, so the verb never races a Crossplane writer (CD4).

The operator's own canary is exempt from (b) and (c) and is served only in its own `DEPLOY_ENVIRONMENT`. `recordNodeRelease` (`app/_facades/deploy/record-node-release.server.ts`) is the ONE release-intent writer; the route, and later the merge webhook, call it. The sequencer process builds one `NodeDeploySequencer` per served env (`NODE_DEPLOY_ENVS`, `env-lanes.ts`) over the shared payer, store, Cloudflare credentials and advisory lock: per env a `cogni-node-deploy-<env>` secrets namespace (the admission policy reads the env from the name), a substrate host (`NODE_DEPLOY_SUBSTRATE_HOSTS`), and an edge guard from that env's catalog cells filtered by the SAME fleet predicate (`NODE_DEPLOY_FLEET_OWNER`; unset admits no remote-source node). The payer env is the release's env. One pass per env, each its own failure domain.

## Observability contract (task.5400)

A node developer has THREE views of one deploy. They are written by the same code, so they agree.

1. **One emit helper.** Every sequencer event (`node_deploy_step`, `node_deploy_provider_strike`, `node_deploy_alert`) goes through `NodeDeploySequencer.record`. It writes the Loki line AND, when the event belongs to an attempt, appends the same step to `node_workload_attempts.steps` (`{step, outcome, reason?, dseq?, provider?, elapsedMs?, at}`). There is no second path. Never log a sequencer event with `this.d.log` directly.
   - Ordinary event persistence is observability only. Qualification reservation/evidence uses the same writer with required persistence: append failure refuses proof. The whole bounded wire-v1 subject is stored as JSON in `reason`; no token or secret is stored.
   - Consecutive identical steps of one attempt collapse into one row (poll loops). Newest 100 steps per attempt are kept (`MAX_ATTEMPT_STEPS`, atomic SQL append).
   - `elapsedMs` (ms since the attempt row was created) rides on every attempt step; `step=activated` also carries `leadTimeMs` (release recorded to serving). Grafana unwraps both.
2. **Release state (derived, never stored).** `deriveReleaseTimeline` computes `releaseState` from terminal admission refusal and attempt phases on every read:
   - `queued` — no attempt yet · `deploying` — an attempt is mid-flight, or a failed lease is still closing
   - `active` — an attempt of the release serves · `parked` — the sequencer's own `release_parked` verdict after 3 consecutive failed attempts, no paid create until a NEW release (`parkedReason` names the count and the last error). Blue keeps serving: when blue's provider is the only screened bidder, the release parks like any other (bug.5582).
   - `failed` — newest attempt failed or its live lease was lost, fewer than 3 failures (retry pending)
   - `superseded` — the desired row points at a newer release (`activatedAt` says if this one ever served). `serving: true` says it STILL backs the live lease; the workload list also returns `servingReleaseId`.
   - Terminal admission refusal is write-once store metadata in existing release JSON. The read model exposes `admissionRefusal` reason/time separately from recovery/serving phase, then projects `parked` when recovery ends. A replacement publication cannot reset it. Resumed attempts retain observe/adopt/confirmed stateless cleanup, never qualification or activation; retained state keeps custody.
   - The sequencer's `alert/release_parked` step (persisted on the release's newest attempt) is the park verdict: it makes the release `parked` even while its third attempt is still `closing`.
   - `leadTimeMs = activatedAt - recordedAt`; `startedAt` is the first attempt's creation. `activatedAt` prefers the write-once `node_workload_attempts.activated_at` (task.5442, set by the sequencer at activation), then the `activated` step. The sequencer also writes a write-once `parked_at` on the newest attempt at its park verdict; the repeating `release_parked` alert never moves it.
   - Read through `GET /deploy/workloads` (`desired.releaseState`, attempts with `steps[]`) and `GET /deploy/workloads/releases/{releaseId}`. Same authz gate as the list (`node.promote_production` for production, `node.manage_envs` for preview, `node.flight` or `node.manage_envs` for candidate-a); a release of another node or env is a 404.
3. **Node-scoped logs.** `GET /api/v1/nodes/{id}/observability/logs?env=<env>&service=deploy` returns ONLY that node's sequencer events: the proxy forces `{env, service="sequencer"} |= "node_deploy" | json | nodeId="<id>"` before any caller stage AND repeats `| nodeId="<id>"` as the last stage (DEPLOY_EVENTS_PIN_BY_LINE in `../nodes/observability-logs.ts`). For EVERY scope the caller's remainder must be whole pipeline stages (`|`, `|=`, `|~`, `!=`, `!~`): no `or`/`and`/`unless` (an `or nodeId=~".+"` would widen the preceding label filter), no braces, no `label_format` writing `nodeId|node|env|service`; anything else is a 400 `invalid_query`. `deploy` is reserved and not a lease service name.

**Rails (bug.5567, bug.5569).** A refused create is persisted (`error: "create refused: ..."`) and never replayed under its `nd:` key; the next attempt takes a new ordinal. A DEFINITIVE refusal (`PayerError.definitive`: the actuator payer marks a create `provider_rejected` definitive ONLY when the actuator's error body carries `nothingBilling: true`, its positive proof that nothing bills under the key: no deployment was opened, or the one opened was closed and re-read closed. A missing field, or a read-back failure after the lease was allocated (now `outcome_unknown`), is never definitive) only proves the create is no longer in flight: it skips the in-flight grace and NOTHING else. Every refusal runs the ONE cleanup chain (`failAttempt` ORPHAN_GUARD) in that tick: observe by key, a found lease is bound, closed and confirmed, nothing found is `failed`. That observe is what settles the actuator's receipt (a `preparing` one through `resolveUncertain`; a rolled-back `allocated` one is already `released` by the create), so the wallet slot is free and no phantom open lease is left. Cost evidence never decides an observe: the actuator reads it only while Console says the lease is active, and a cost failure is a `compute_cost_observation_failed` warn, never a `ledger_unavailable` refusal. A proof whose `/version` probe through the provider ingress answers 404 on every probe for `hostNotRoutedMs` (60 s; the provider does not route our custom host) fails `host_not_routed` at once with a `provider_strike`, through the normal close path (blue and the edge untouched); the failed-try exclusion then keeps that provider out of the release. Any other proof failure keeps the full `proofMs` window. An unbound attempt whose `observe` keeps throwing is failed `orphan_suspect:` after `observeUnavailableMs` (15 min from the first failure) with `alert/orphan_suspect` (carries the cogniKey; the lease is NOT claimed closed and nothing re-observes it, so a human acts on the alert). A live app lease whose `/version` serves the exact sha but whose `/readyz` fails is `alert/dependency_down`: kept, never closed or redeployed; the lease is closed only after `/version` itself fails for 15 min (a class change restarts that clock).

Operator-only: the Grafana dashboard `cogni-node-deploy` and the alerts in `infra/grafana/alerts/node-deploy.alerts.yaml` (release parked, no leader for 10m, leadership lost, repeated proof_timeout, edge restore failed). A failed cutover is decided durably on the attempt (`error` `rollback_pending: ...`, green stays `proven`); green closes only after the edge is back on blue, so a failing restore holds the lane and pages `edge_restore_failed` (bug.5587). The no-leader alert relies on the bootstrap's once-a-minute `node_deploy_sequencer_leader {heartbeat:true}`.

**Hairpin rule.** An app cannot reach a state lease's public forwarded port on its own provider, so every app create excludes blue's provider AND the provider of each bound state workload's active lease (`excludeProviders`, deduped, max 16, logged as step `providers_excluded`).

**Provider memory (story.5137, bug.5586).** A new app create also excludes (1) FLEET: each provider with ONE CONFIRMED `host_not_routed` strike in the last 24 h on ANY lane of the store (every node, env and workload: one operator's store spans every env it serves). Confirmed = the struck attempt's release also served (`proven|active|retiring|retired|lost`) on a DIFFERENT provider, so the app serves its host and the 404 was that provider's ingress; a broken build that 404s everywhere confirms nothing. Read by `StorePort.hostNotRoutedProviders` (phase `closing|failed`, time window, limit 16, correlated EXISTS on `(release_id, attempt)`). (2) LANE: each provider struck `proof_timeout` or `host_not_routed` on the SAME lane (node + env + workload) at least 2 times in the last 24 h, across releases. A state create takes no fleet entry (it is reached by port, not host). No lockout: memory never names the lane's most recent served provider (newest active, retiring, retired or lost attempt, so the hairpin rule alone decides blue), any provider that served the lane in the window, or the last admitted (`appProviders`) provider still open. With no allowlist (production: open market) there is no last-admitted floor. Memory fills only the slots left under the wire's 16: fleet first (newest strike first), lane memory is dropped first. The `providers_excluded` step names both (`fleetExcluded` + `fleetConfirmedBy` provider -> release id + `fleet host_not_routed: <p> confirmed by release <id>`, `remembered` + `memory:` in the reason).

## Node app runtime env and placement (task.5405)

A node APP of a non-operator node gets the SAME env the retired Crossplane lane rendered, with OpenBao as custodian. The operator's own workloads (slug `operator`) and the dev harness (no `runtime` dep) get only `RELEASE_SHA` and bindings.

- **Env.** `node-app-env.ts` (`nodeAppEnv`, pure, parity-pinned key by key in `node-app-env.test.ts` against `infra/crossplane/xcomputeworkload/composition.yaml` (deleted by task.5411; read it at `37fbd413f1^`) l.185-284). Order, later wins: `HOST/HOSTNAME/PORT`, `APP_ENV`, `DEPLOY_ENVIRONMENT`, `COGNI_REPO_SHA`, substrate topology (`nodeAppSubstrateBinding`: egress = the VM host from `NODE_DEPLOY_SUBSTRATE_HOST[S]`; `transport: "mesh"` = the `cogni-substrate` companion, ports only from `substrate-ports.ts`, and a bucket `DOLTGRES_URL` / shared-VM Postgres DSN rebound only when its host is the lane VM name or one of `substrateAddresses`, else refused or left on its dedicated cell; task.5432), bucket secrets, `COGNI_NODE_ID`, DB pool maxes (catalog), identity (`DOMAIN`, `NODE_NAME`, `NEXTAUTH_URL`, ...). Then `RELEASE_SHA`, then declared state bindings (CD2: a binding beats the bucket). Injected env beats a same-named declared `env`. The trusted operator `DOMAIN` comes from `NODE_DEPLOY_OPERATOR_DOMAIN_ROOT` and the workload lane; a state binding targeting `DOMAIN` is refused before payment.
- **Binding destinations.** `runtimeOwnedEnvKeys` uses the same field definitions as `nodeAppEnv`, `workerEnv` and `releaseIdentityEnv`. Full-set admission rejects sibling URLs at each consumer's injected destinations, including optional blocks and renamed secret outputs, before environment pruning. Runtime precedence is unchanged.
- **Declared keys only.** An `app` release carries `secretKeys` (value-free): the `cogni-node-app-v1` profile keys, plus the app service's declared `secret_refs`, plus every entry of the node's `.cogni/secrets-catalog.yaml` whose `workloads` names the app service, all AT `sourceSha`, computed in `declarations.ts` (bug.5254). A worker gets only its own `secret_refs` plus catalog entries naming it. The catalog is checked whole by `parseNodeSecretsCatalog` (`@cogni/repo-spec`); an invalid catalog, or a catalog entry that projects a substrate-reserved, fleet-inherited or off-cluster-denied key, is refused `secrets_catalog_refused` (422). `secret_refs` is the transition input; the catalog entry is the one declaration. Generation: when the release records, the facade creates any missing key the spec carries that the catalog declares `source: agent` (create-if-absent, KV check-and-set, never overwrite). It does so only when this operator custodies the lane and the caller holds `node.manage_secrets`; otherwise the sequencer waits on `missing_keys` (event `feature.node_deploy.secret_generation`). A denylisted key (`OFF_CLUSTER_WORKLOAD_DENIED_KEYS`) is refused at lowering (`secret_ref_refused`, 422). A fleet-inherited key that merely sits in the node's bucket (`GH_WEBHOOK_SECRET`, `POSTHOG_API_KEY`, ...) is never on the list and never delivered. `LITELLM_VIRTUAL_KEY` is delivered as `LITELLM_MASTER_KEY`. Every declared key (minus those a state binding supplies) must be present.
- **Worker workloads (task.5272).** A manifest whose workload name matches a repo-spec service with NO `runtime_profile`, beside a distinct `cogni-node-app-v1` service, lowers with `runtimeProfile: "worker"` and `secretKeys` = that service's own `secret_refs` ONLY. The sequencer then builds `workerEnv` (`HOST`, `PORT`, `DEPLOY_ENVIRONMENT`, `COGNI_REPO_SHA`, the declared secrets) instead of `nodeAppEnv`: no node-app profile, database, auth or substrate env, and no DB CA start wrapper. It still has a route (its own `<slug>-<workload>` host) and the same blue/green proof. Anything that does not match both conditions stays the node app (fail safe). Only a worker may claim `<slug>-<workload>`; `workerHostRefusal` (pre-create, `edge.ts`) refuses a workload name that is not one plain label or is `test`/`preview`/`dev`, a host any OTHER catalog slug owns in any env (`NodeCatalogPort.slugs()`), and the node's own host in another env.
- **Secrets (existing custody path).** `NodeRuntimeSecretsPort` (`EsoNodeRuntimeSecrets`) ensures ONE ExternalSecret `nd-<slug>-env` in the sequencer's OWN namespace (`NODE_DEPLOY_SECRETS_NAMESPACE`): `ClusterSecretStore openbao-backend` (ESO's `eso-reader`), explicit `data:` entries `{secretKey: K, remoteRef: {key: <env>/<slug>, property: K}}` for exactly the declared keys (NO `dataFrom: extract`), target `nd-<slug>-env` (Owner, 5m). The slug comes from the image catalog mapping, never caller text. It waits a bounded 20 s for Ready, then reads the target Secret and returns exactly the requested keys. Custody stays in OpenBao; there is NO new OpenBao role and no root token. The sequencer is the ONLY writer of that ExternalSecret (Role: externalsecrets get/create/patch/update in its namespace only). A declared key with no OpenBao property leaves the ExternalSecret not Ready, so nothing is paid.
- **Cluster-side bound.** ESO's store reads `cogni/data/*`, so the sequencer's ExternalSecret rights are fenced by a `ValidatingAdmissionPolicy` + binding (`infra/k8s/base/node-deploy-sequencer/admission-policy.yaml`, bound per overlay to `cogni-node-deploy-<env>`, `failurePolicy: Fail`, `Deny`): store pinned to `ClusterSecretStore/openbao-backend`, no `dataFrom`, no per-entry `sourceRef`, every key `<this env>/<slug>` and never `operator`, `scheduler-worker`, `akash-tx-actuator`, `_system`, `_shared`, `openfga`, `litellm`, `doltgres`, `temporal`, `postgres`, `redis`, `grafana`, `loki` or any bucket containing `database`; target `nd-*`. Pinned by `tests/ci-invariants/node-deploy-sequencer-admission.spec.ts`. Sequencer code is not the boundary.
- **Fleet workload zone.** Scoped release reads retain fleet/environment authorization without requiring new DNS admission. `bootstrap/node-deploy-lanes.ts` is the one lane composition. An invalid plain configuration keeps the existing recovery lanes running with `httpAdmissionRefusal` set (the binding error code) and no edge: a fresh app waits as `dependency/waiting` before any attempt or payment, and a proven green waits at cutover instead of being closed. The route, declaration lowering, sequencer ownership checks and edge adapter consume the validated fleet binding (`resolveWorkloadZoneBinding`). `NODE_DEPLOY_WORKLOAD_ZONE` is explicit plain ConfigMap data: canonical `cognidao.org`, isolated test fleet `cogni-testing.org`. `NODE_DEPLOY_FLEET_OWNER` reads the same ConfigMap owner as the route. No auth `DOMAIN` or substrate `FORK_DOMAIN_ROOT` fallback exists. The zone id is resolved BY NAME with the zone-scoped Cloudflare token at boot (story.5137), so it can never name a zone that token cannot read; a failed lookup leaves the edge unconfigured. A declaration must name the node's production-form host at its immutable source; `hostForEnv` adds the usual suffix. The edge guard is catalog-derived in that zone; apex/operator/protected names, foreign node/env/fleet and sibling collisions refuse before paid creation. Native zone-ID/name agreement is re-verified, bounded and typed; a changed token invalidates cached proof. Read access is not edit permission. Recorded releases keep their hosts; ambiguous paid effects retain observe/readback/cleanup authority.
- **NO_HALF_ENV.** A missing key, an ExternalSecret that is not Ready, a node the image catalog does not know, or a malformed catalog cell throws `DependencyNotReady` BEFORE the attempt row exists: step `dependency/waiting` names the keys (never values), nothing is paid, no attempt is burned, and the next tick retries.
- **Catalog.** `NodeCatalogPort` (`ImageCatalogNodes`) resolves node id -> slug + row from `/app/infra/catalog` baked in the image. `node-catalog-policy.ts` reads `required_placement_countries[<env>]` (sent as `spec.placement.requiredCountryCodes`; apps only) and `database.<env>.runtimePoolLimits`.
- **Placement.** Node app creates send no provider pin (`NODE_DEPLOY_APP_PROVIDERS` is gone; unset sends no `allowProviders`, bug.5569). The actuator's `AKASH_ALLOWED_PROVIDERS` is empty since PR #3056, so provider screening, host-routing strikes and the release's country set decide placement. The set is the node's manifest annotation `cogni.dev/placement-countries[-<env>]`, lowered into the release spec at `sourceSha` (story.5141); a catalog `required_placement_countries.<env>` cell is the bridge for nodes not yet moved. Both are sent as `spec.placement.requiredCountryCodes`. `recordNodeRelease` refuses both sources (409 `placement_source_conflict`, CD4) and a set naming a fleet-refused country (422 `placement_country_refused`, `FLEET_REFUSED_PLACEMENT_COUNTRIES`); the sequencer waits unpaid if a catalog cell appears after the record. Every lane reaches the shared substrate over its env mesh; the VM firewall admits no provider egress CIDR (catalog `compute_egress_cidrs` was deleted by task.5428). A provider whose attempt fails the proof, the old release keeps serving, and the next attempt of the same release sends that provider in `excludeProviders` (with blue's provider and bound state providers): the sequencer adds the provider of every earlier attempt of that release that failed or was lost after binding a lease. A refused create bound no provider and adds none; another release's providers are not excluded.
- **Start command.** A node app that receives a DSN starts through `databaseConsumerCommand` (DB CA trust wrapper), as the Crossplane lane did.
- **Green migrates itself (task.5408).** Every node app also receives DATABASE_MIGRATION_URL. It is read by the same `nd-<slug>-env` ExternalSecret from the node's own `<env>/<slug>-database-migration` bucket (the one database bucket the admission policy admits, for that key only). A node whose DATABASE_URL is bound to its own state lease gets it from that binding instead (bindings.ts OWN_STATE_MIGRATES_ITSELF); the shared bucket DSN never reaches a dedicated resource. The start wrapper then runs `node /app/app/migrate.mjs /app/app/migrations` with it, then `migrate-doltgres.mjs` with DOLTGRES_URL when set, unsets it and execs the app. A migrator failure stops the container, so the lease never proves and blue keeps serving (CD6). Migrations must be expand-only while blue serves: a node authoring rule, not enforced here (task.5419).

## Private stateless companions

Score owns 1–8 containers and the unique public entry by route target/readiness port. `declarations.ts` bridges same-SHA repo-spec build metadata, secret refs, sibling bindings and env gates; it checks the whole set before pruning. Retained state keeps its separate lifecycle.

`artifact-selection.ts` reuses the whole bundle-v1 validators and env cascade. The existing release JSON carries the frozen artifact plan and accepted selected digest set. `pinResolvedBundle` seals JSON plus primary `resolved_image` under a source-wide advisory lock; later envs read the accepted OCI bundle by digest. Every selected image manifest is checked by accepted digest before an attempt and before a new paid call, including resumed attempts and cross-env reuse. Missing or unreadable images wait; invalid publications park explicitly.

Runtime assembly projects the selected union of secret keys once per assembly, then gives each consumer its declared subset. Only the public app gets the app profile. Sibling URLs derive once from selected private names/ports. The existing payer array/private SDL carries the whole authorized release.

`qualification.ts` implements wire v1 using AUTH_SECRET HKDF-SHA256 and jose. The observed static ingress of the green attempt is the DNS target, TLS SNI, verified certificate name and HTTP Host (bug.5568: a provider answered 421 to static SNI with the canonical Host). Redirects are refused. A failed qualify or readback emits one `qualification_diagnostic` step (mode, stage, allowlisted code, HTTP status, elapsed ms, attempt, allocation, ingress); it never carries the bearer, headers, body or a raw error, and it does not change the failure decision. A bounded useful-work result is persisted before proven, then fresh non-dispatching readback must match attempt/allocation and every selected companion boot before edge movement. Signed readiness targets require fresh 200 observations at each declared port/path, with exact companion coverage; the saved receipt helper must agree with its companion observation. Capability releases keep blue when qualification fails or is unknown. Single-container releases without capability keep the existing path. No provider or hostname algorithm changes.

## Substrate mesh (task.5431, hub node-service-delivery sections 3, 4, 6)

- **Lane switch.** `NODE_DEPLOY_SUBSTRATE_TRANSPORTS` (`env=mesh[:<tailnet>]|egress`, default egress; tailnet defaults to the env) is a lane property. Since task.5428 no VM firewall admits provider egress, so an `egress` attempt cannot reach the substrate: switching a lane back to egress needs that deletion reverted first (`drain` itself still works). Every lane gets `SequencerDeps.mesh` over `/var/run/headscale/<tailnet>/headscale.sock`: `mint` for a mesh lane (control URL `https://mesh-<tailnet>.<zone>`, zone = `NODE_DEPLOY_WORKLOAD_ZONE`, the tailnet table zone; task.5428), `drain` for an egress lane (revoke, sweep and Secret delete only while mesh attempts are left; no Headscale call otherwise; never mints or rolls). The gateway publish is read at `/.well-known/cogni-mesh/<tailnet>/substrate-gw.json`.
- **Transport per attempt (HR 18).** `attemptTransport` decides before the row exists and `insertAttempt` writes it (`node_workload_attempts.transport`): mesh only with a retained blue, a node that served on the mesh, or a new release of a workload that serves nowhere. A create never closes blue first, so a serving blue is always retained; while minting is closed a mesh create waits unpaid and blue keeps serving.
- **One key per attempt (HR 5, HR 23).** Under the lane's one Headscale write lock: reconcile, mint (reusable, ephemeral, `tag:node-<id>`), write the key id, the coordinator epoch (owner `cogni-mesh-<tailnet>` creation time) and the key's creation time to the row (`mesh` jsonb), store the value create-once in `nd-<id8>-<workload>-mesh-<release>-a<n>`, then pay. A stored id from another epoch, or whose listed key has another creation time, is void: it never revokes, protects or counts anything. No key yet = `mesh_key_pending: <reason>`, unpaid, resumed next tick.
- **Companions (CD1, CD3, HR 3, 16, 21).** `cogni-mesh` (tailscale 1.104.4 userspace, uid 10001, no `--advertise-tags`, `TS_NO_LOGS_NO_SUPPORT`) and `cogni-substrate` (socat, one listener per bound port) are appended by the sequencer, digests pinned by the release's first mesh attempt. Entrypoints are one line each (create uid, `su`, `exec` the stock binary): a recorded CD9 exception (no SDL `runAsUser`, no custom image). `nodeAppEnv` binds the app to `cogni-substrate` (task.5432); `nodeAppSubstrateBinding(...).ports` from the same input = the listeners = the grant. The VM host is resolved once per mesh pass (`ProbePort.resolveAddresses`).
- **No gateway, no pay (HR 23).** A mint is refused unless the owner's creation time is still the reconciled epoch and the tailnet has exactly one `tag:substrate` device, tagged exactly that and online. The attempt waits unpaid (`mesh_key_pending: mint_gateway_<absent|offline|multiple|tags>` or `mint_epoch_changed`) and `node_mesh_mint_refused` (warn, throttled) names it.
- **Mesh pass (60 s, leader lock, same write lock).** Policy (deny-all first) -> admin-surface check -> one gateway, recomputed (stateless, every pass: a wrong-tag `tag:substrate` device is deleted as `node_mesh_substrate_mismatch`; with 2+ online gateways keep the one approved this pass from a verified request, else the oldest, and delete the other online ones as a mismatch; an offline gateway older than the kept online one is deleted, `node_mesh_substrate_superseded`; nothing is deleted when none is online; a restart or failed delete is retried by the next pass) -> `substrate-gw` approval (HR 11: a fresh verified auth id not yet approved by this process; a new device not exactly `[tag:substrate]` is deleted; else it is kept and the rule runs at once; no key compare, no second stage) -> revoke terminal attempts (a retiring blue only once retired) -> delete revoked Secrets one pass later -> sweep (live set re-read) -> device check (mint lanes; active attempts; 10 min absent over consecutive successful reads rolls one new attempt; cap 2 per env; >1 online device for 2 min = `node_mesh_device_clone`). Events: `node_mesh_*`.

## Responsibilities

- This directory **does**: sequence deploys over ports, emit one event stream, project the read model.
- This directory **does not**: perform IO, import adapters, decide authz, or store derived state.

## Standards

- A new sequencer event goes through `record`; a new persisted field needs a contract field and a test in `sequencer-timeline.test.ts`.
- A new release state or rule changes `release-view.ts`, the contract enum and `release-view.test.ts` together.
- Schema changes to the attempts table follow the `schema-update` skill (additive, nullable).

## Notes

- The sequencer holds no IO: ports are injected, so the same state machine runs over fakes in tests and over the actuator in production.
- `release-view.ts` only reads rows the sequencer wrote; it never decides anything the sequencer decides.
