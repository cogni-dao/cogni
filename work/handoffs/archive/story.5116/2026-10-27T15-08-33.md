# Handoff: Cogni — one hub-grounded, long-running mission agent

## Mission

Pickup (you are an experienced LangGraph dev): you own **Cogni**, the shared agent every node
runs to advance its mission. It reads this node's goals + knowledge + work items + git, then
produces a **grounded decision** about what to prioritize/refine/create. The plumbing works and
the graph now completes, but two things are wrong at the core: (1) the agent's output is an
ad-hoc `{summary, items[]}` JSON blob, **not** the designed artifact; (2) structured output is
hand-coaxed, not demanded natively. Do not re-architect the graph — it is a clean compiled
`StateGraph` and langgraph-dev-transparent. Fix the output to the designed concept and make it
deep + reliable.

## Goal

**End state.** On candidate, a scheduled/chat run of `cogni` investigates deeply across all three
planes and emits the designed decision artifact, proven by a readable Langfuse trace.

- **The output IS an EDO Decision.** EDO = Event–**Decision**–Outcome. Per
  [dao-goals-design](https://cognidao.org/knowledge/dao-goals-design) the prioritizer's _proposal
  is a `decision`_ that `derives_from` a goal; [mission-loop-roadmap](https://cognidao.org/knowledge/mission-loop-roadmap)
  R1 _"files a proposal decision only when the plan changes."_ The decision tool already exists:
  `core__edo_decide` (packages/ai-tools/src/tools/edo-decide.ts; also `edo_hypothesize`,
  `edo_record_outcome`). The current code emits a parallel JSON "proposal" and the prompt says
  "No EDO" — that is the drift to correct. Outcome-grading (record_outcome) is the later R5 rung.
- **Core eval (Derek).** Prove _retrieve · refine · create_ with real DEPTH — dozens of grounded
  reads, not 4. "Touched each plane once" and a schema-valid blob are NOT quality. A valid goal
  id / successful search / literal "next:" is not quality.
- **E2E / candidate proof.** Flight the PR head SHA via the operator API (POST /api/v1/vcs/flight,
  never a personal gh dispatch), confirm `https://test.cognidao.org/version` `buildSha == head`,
  then run cogni there and read its trace via the node-traces gateway. Pass = a real `edo_decide`
  (or `decision` entry) grounded in deep reads + a readable trace. Then `/validate-candidate`.

## Design / Implementation Target

1. **Output = EDO decision.** Replace the ad-hoc `{summary, items[]}` proposal with a real
   `core__edo_decide` call (the Decision), `derives_from` the cited goal. Drop the "No EDO" prompt
   rule. Keep it propose-only in the sense of "no work-item/knowledge-body writes beyond the
   decision"; filing a decision is R1's own write lane — confirm the autonomy-rung scope with Derek.
2. **Demand structured output natively.** Stop hand-parsing + the `proposal_schema_invalid` catch.
   Use the model's native structured output (tool-call with the schema / json_schema response_format
   via the completionFn), so the provider enforces validity. Loosen over-strict constraints (`.strict()`).
3. **Gather DEEPLY.** Push the investigate loop to read many items/entries and follow threads before
   deciding; rewrite the coverage grader from "touched each plane" to _depth of grounded reasoning_.
4. **Must not regress:** keep the compiled StateGraph transparent in langgraph dev; recursionLimit is
   a derived backstop (>2× the step cap), never the real bound; no new graph/dashboard/scheduler;
   preserve authorization, billing, tracing, host-owned sourceContext (never model-chosen); human-only
   hub merge. **Do not keep growing this PR** — split follow-ups into linked items.
